# Phase 188 — show received autopilot warnings on Operate

## Goal and scope

The operator requested Mission Planner-like visibility for errors such as “PreArm: Compass 1 not calibrated.” The app already parsed, assembled and retained selected-source `STATUSTEXT` but placed its text in Diagnostics. This change projects the newest severity 0–4 message on Operate with its reported level and receive age. Tapping the banner opens Diagnostics; that page now places the message panel near its top and includes the last warning if later routine messages pushed it beyond the five recent rows. No new receive route, parameter change, request or vehicle command was added.

## Flow, ownership and limits

Incoming untrusted bytes → `MavlinkParser` CRC/payload check → `MavlinkSession.routeSelectedAutopilot` source selection → `StatusTextAssembler` → `VehicleRepositoryImpl.onStatusText` → bounded 50-message `VehicleState.statusTexts` in session memory → `latestAutopilotWarning`/Compose banner. The receive coroutine writes the state; Compose reads it. A new session replaces the state; disconnection is hidden by `forDisplay`. Selection uses the protocol's severity values 0–4, which cover emergency through warning per the [MAVLink message definition](https://mavlink.io/en/messages/common.html#MAV_SEVERITY). The banner says **last reported** because there is no verified resolution event. A future/invalid wall-clock timestamp displays an unavailable age.

## Risk and remaining acceptance
