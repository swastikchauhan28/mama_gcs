# Phase 232 — offline field download recovery

## Goal and scope

Add visible progress, explicit cancellation and operator-started resume for incomplete OpenFreeMap field packs. Reuse MapLibre's existing offline region database; preserve saved missions, map-provider selection, telemetry and vehicle-command boundaries. The user approved this bounded phase on 2026-11-24. Baseline revision `de01a6e81cc5d6ba3d47693334b8d651b5201b64` is a recovery reference, not a qualified release. Phase 230/231 changes and older demo outputs were already dirty and must be preserved.

## Plan and acceptance

Read persisted region status before enabling a new download. Display saved resource count and a percentage only when MapLibre reports a precise required-resource total. Cancel only the active field download, retain the incomplete region and prevent stale callbacks from calling it ready. Resume an incomplete saved pack with its original bounds/style under a fresh request/byte budget. A disposable emulator should run interruption and resume in separate instrumentation processes, confirm the pack remains incomplete after cancellation, then reach complete and render offline. Run the usual JVM/build/lint gate and visually inspect the UI. The synthetic test pack must be removed after the test.

## Implementation and data path

`MapSettingsScreen` reads `OfflineFieldMaps.state`: an incomplete pack shows its saved resource count and, only when MapLibre reports a precise total, a percentage and progress bar. It offers Cancel for the active operation and Resume for each incomplete saved pack, plus the existing confirmed Remove. The current draft button also resumes a matching incomplete area. Refresh saved maps retries a failed status read. The UI never promotes a pack to Ready from its percentage; only `OfflineRegionStatus.isComplete` does that.

`OfflineFieldMaps` keeps only an operation token, region ID and weak native-region reference in memory. MapLibre's app-private database retains bounds, name and resources. Cancellation deactivates the active region and leaves it in the database. A new process lists saved regions, normalizes a stranded native ACTIVE flag to inactive, and reads all region statuses before enabling another download. Resume validates the fixed OpenFreeMap style, zoom 12–18, disabled bulk ideographs and at most 2,000 estimated tiles before activating the saved region. A fresh request/byte budget applies to each operator-started resume. Late native callbacks are ignored using the operation token; no background retry, new destination, dependency, schema, account action or vehicle command was added.

## Limits and next step

The test disables MapLibre networking, not the entire emulator radio stack. It uses synthetic areas, not the operator's actual field. A precise resource count may change while MapLibre discovers assets, so the percentage is progress information, not an ETA or surveyed-area guarantee. A process killed before MapLibre creates a region may leave nothing to resume; the operator can start a new download. The owner should review the diff, then download and inspect the real field on a phone with connectivity off before relying on it. No commit or push was requested. See D-232-01.
