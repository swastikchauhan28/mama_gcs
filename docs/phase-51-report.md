## Scope and decision

The input is the existing `app/build/reports/lint-results-debug.txt` warning list. See [D-051-01](DECISIONS.md#d-051-01-fix-narrow-source-lint-warnings-without-changing-behavior). The optional `modifier` argument was moved to the first optional position in `MapScreen`, `SettingsScreen`, and `VescBluetoothDiscoveryScreen`; all affected positional in-repository calls were updated to named arguments. `VehicleMap` now uses the already-present Core KTX `createBitmap` helper for the 48×48 ARGB_8888 home-label image, retaining the drawing and density setup.

Data flow, persistence, permissions, dependency versions, network destinations, MAVLink parsing, radio/vehicle trust, command availability, and physical safety gates are unchanged. The VESC/BLE screen still consumes supplied UI state and callbacks; the map helper creates only an in-memory icon. No warning was suppressed or assertion weakened. An emulator-only screenshot was added to the existing offline local-style home-marker test for visual review; it contains synthetic coordinates and is kept under ignored `app/build/`.

## Lint disposition

Fresh lint: **0 errors, 28 warnings**, down from 32. The remaining 28 are 14 `GradleDependency`, 10 `NewerVersionAvailable`, 2 `AndroidGradlePluginVersion`, 1 `UnusedAttribute` (`BLUETOOTH_SCAN` API-31 flag with minSdk 26), and 1 `DiscouragedApi` (debug-only landscape orientation). Version notices need a separately reviewed toolchain/dependency upgrade, not an automatic bump; the manifest flag and debug orientation touch permission/configuration policy and were deliberately left unchanged. This is a disposition, not a claim that the remaining warnings are harmless. Compiler/kapt deprecation/processor messages are separate from the lint count and remain unaddressed.
