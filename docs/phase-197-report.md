# Phase 197 — Current Classic serial-card detail

Date: 2026-11-17. Baseline `9b9b740` on `main`. The Phase 196 source/tests and live T12_485 records were already uncommitted; this phase preserves them. The user approved the bounded display fix and then specifically requested phone USB testing after the disposable emulator failed Android health preflight. Model/version unavailable.

## Symptom, path and design

`BluetoothTransport.connect` sets `ConnectionState.detail` once when the socket opens: `Serial link open; waiting for MAVLink heartbeat`. The Classic screen previously displayed that unchanged opening detail inside the serial card even while its separate `MAVLink heartbeat` field, derived from `ClassicConnectionCheck.assess`, read `FRESH`. The Phase 196 phone check observed the contradiction. See decision `D-197-01` in `DECISIONS.md`.

`classicSerialLinkDetail` now projects the card detail from the same current-session assessment used by the checklist. With a fresh accepted heartbeat it says a fresh heartbeat was received; when bytes are stale it says no recent bytes; when current bytes lack a confirmed heartbeat it says that heartbeat is not confirmed. Before evidence exists, the opening detail remains; an error or non-open connection retains its transport detail. The transport, decoder, five-second freshness/session boundaries, selection, persistence, permissions, dependencies, network behavior and disabled command path were not changed. The serial stream remains untrusted: this display does not authenticate T12_485 or establish RC movement, wiring or vehicle safety.

## Limits, review and recovery

The waiting and stale text paths have JVM regressions and a focused Android UI test that passed on the physical phone; the emulator still did not pass its Android health gate. A live T12_485 session showed the fresh state. A separate synthetic phone UI test exercised waiting, fresh, stale and closed states without opening Bluetooth or sending commands. No deliberate radio power-loss, real-link disconnect, stick motion, vehicle command or mission upload was performed. The existing first-session disconnect and long-run reliability remain separate questions. Review the scoped screen/test diff, the unchanged trust and command boundaries, and the emulator/phone evidence. This display-only change has no migration.
