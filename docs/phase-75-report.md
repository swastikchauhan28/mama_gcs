## Change and boundary

The shared Add/Edit waypoint and field-outline dialog now requests a decimal keypad for latitude and longitude. Each field has a labelled `±` control to add or remove a leading minus sign, so negative coordinates remain possible even if an IME omits a sign key. The instruction line points to that control. The dialog keeps each value as a `rememberSaveable` string bounded to 32 characters; the sign control does not truncate a full-length unsigned value. It replaces a leading plus sign in place and trims surrounding whitespace only when explicitly tapped. The existing finite-number parser, latitude/longitude ranges, error guidance and Add/Apply gate remain unchanged.

The path is local UI input → in-memory dialog values → existing `MissionPlanAction` callback only after explicit Add/Apply. It adds no persistence, network destination, dependency, permission, telemetry or hardware command. The `KeyboardType.Decimal` hint is advisory to Android keyboards, not input validation or a guarantee across IMEs. The [Android KeyboardType reference](https://developer.android.com/reference/kotlin/androidx/compose/ui/text/input/KeyboardType) describes that limitation.
