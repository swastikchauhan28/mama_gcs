# Phase 73 — Explain invalid local coordinates

Date: 2026-10-27

Baseline: `9bb331e73e321f7d53c9cd3c017d704f33d7389b` plus uncommitted Phases 71–72

Scope: the shared Add/Edit waypoint and field-outline coordinate dialog. Hardware remains on hold.

## Change and boundary

Nonblank invalid latitude and longitude now show field-level range guidance. The dialog still caps each string at 32 characters, parses finite decimal degrees, accepts latitude only in -90…90 and longitude only in -180…180, and disables Add/Apply until both are valid. Empty fields retain the prior disabled-without-error behavior. The existing Done action and local action callbacks are unchanged. When the focused longitude becomes invalid, a transient Compose `BringIntoViewRequester` scrolls its existing dialog content so the error is readable above the IME. Its focus flag is in-memory UI state only; no new persistence or external input is introduced.

The new test uses synthetic coordinates, a synthetic route and an in-memory action list. `MissionScreen` dispatches only the existing local `MissionPlanAction` callback in this fixture; it does not access a route repository, telemetry transport or vehicle command path. The same dialog also edits field-outline vertices, so its existing local mission regression was rerun.
