# Phase 243: Google Maps planned-area preview verification

## Goal and scope

Verify the Phase 242 read-only planned-area preview on a Google APIs disposable emulator with a configured debug Maps key and a synthetic two-point route. Acceptance requires loaded Google tiles, automatic framing of both numbered points, no rover marker, and the existing recovery path for an unavailable map. No phone, Cube, radio, caster or saved operator route is involved. The user approved this software-only phase; commit and push were not requested.

## Path and trust boundaries

The test supplies a transient MissionDraft with two bounded synthetic coordinates to RouteAreaPreviewScreen through LocalBasemapStyle.GOOGLE_STREETS. The screen delegates to the existing VehicleMap Google renderer, which uses the configured restricted debug Maps key for normal tile requests. The test checks the read-only label, availability notice, enabled Fit area action and GoogleMap camera/projection after automatic fit without tapping Fit area. It captures a screenshot for visual inspection of tiles and numbered markers. It does not write a saved draft or send a vehicle command. Google Maps service and emulator Android services are external availability dependencies; a camera assertion alone cannot prove tile or marker rendering.
