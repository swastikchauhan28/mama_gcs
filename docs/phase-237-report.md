# Phase 237 — saved-area map visual verification

## Goal and scope

The owner approved an emulator-only follow-up to Phase 236: inspect a selected synthetic saved map area online and offline, verify visible blue pack borders and map tiles, and investigate the prior black MapLibre captures. No operator phone, real field, Cube, rover command or saved route is involved. Baseline `0d6cafbeb971de894e5bec44d9abb10b4e39e790` on `main`; only the older `output/` demo deliverables were untracked at start.

The intended path is Maps settings → View saved area → dedicated Field map. `MapSettingsScreen` reads the native `OfflineFieldMaps.state`; navigation passes only a pack ID; `SavedPackMapScreen` refreshes the native pack list; `VehicleMap` loads the existing OpenFreeMap Field style, projects completed pack rectangles as blue lines and fits the selected bounds. The pack list is app-private MapLibre state and the camera geometry is transient. The online map may use the existing OpenFreeMap destination; the offline check must verify Android has no active network. A native-complete pack is an availability hint, not a tile audit or field survey.

The alternative to changing map code now is to first compare a healthy emulator with Phase 235's visible-border screenshot and Phase 236's black native capture. A renderer or Android System UI failure can make a map test pass camera/layer assertions without producing visible pixels. App code will change only if the evidence identifies an app-side defect.

## Final emulator evidence and decision

- The fresh `MamaGcs_Phase237_API34` emulator booted without a snapshot or window. Its 30-second launcher preflight had no Android error or ANR. The existing production debug APK and revised test APK installed without touching the operator phone. The final `:app:assembleDebugAndroidTest --no-daemon --max-workers=1 --console=plain` passed (`app/build/phase237-test-build-final.txt`; 7 tasks executed, 53 up-to-date).
- The selected-pack regression passed online with two adjacent synthetic packs. A new delayed capture initially failed because it called `loadedMap()` before Compose attached the MapView; the corrected test waited for the View saved area path. A later run passed geometry/layer assertions but produced a black MapLibre `map.snapshot()` image. An actual Android screen capture during the same test showed visible blue borders. MapLibre native and Compose view snapshots therefore cannot be trusted as rendered-screen evidence on this emulator. The new test uses `UiAutomation.takeScreenshot()` after the map settles and retains the existing camera and layer assertions. Its final online run passed (`phase237-final-revised-result.txt`) and saved `phase237-final-revised-onscreen.png` with nonblack map pixels.
- The first network-off transition was not counted as offline evidence: Android initially still reported an active default network and rejected a direct AIRPLANE_MODE broadcast. The supported `adb shell cmd connectivity airplane-mode enable` command was used instead. Only after `dumpsys connectivity` reported `Active default network: none` did the separate offline test run. Its instrumentation passed (`phase237-offline-verified-result.txt`), and the actual screen `phase237-offline-verified-onscreen.png` visibly shows roads, labels and blue adjacent pack borders. The test's `finally` removed the synthetic packs. Emulator networking was restored; the final online run passed with an active default network, and `phase237-final-online-onscreen.png` shows the same street detail and borders. These controlled synthetic coordinates around Bengaluru are not the operator's field.
- The view displays `NOT SAVED OFFLINE · Field maps cover zoom 12–18 only` at the fitted zoom. Visible cached tiles at that zoom do not prove complete saved coverage there; the warning is appropriate. No production map-code defect was reproduced. A Gmail process crash appeared in historical emulator logcat, but no Mama GCS crash or Android dialog affected the final runs.

Decision D-237-01 (2026-11-25): use actual Android screen captures for visual acceptance, with camera/layer assertions for geometry. Alternatives were trusting the native MapLibre snapshot or changing production renderer code. The snapshot produced black while the visible screen rendered, and no production defect was reproduced. Cost: screenshots still require visual review and the synthetic pack does not audit every stored tile. Revisit if a real device displays a black map or a tested capture method later contradicts the screen. AI model/version: unavailable.

## Acceptance and remaining limits

The clean disposable-emulator preflight, selected synthetic pack path, rendered blue borders and street detail are verified online and with no active default network. Native snapshot pixels are not an acceptance signal because they contradicted the actual Android screen. The zoom-limit warning remained visible. Actual-field phone testing still needs field coordinates, and none of this proves rover navigation or physical map accuracy. No commit or push is authorized by this phase approval alone.
