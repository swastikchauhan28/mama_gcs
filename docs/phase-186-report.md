# Phase 186 — Guard and verify the mission-warning picker screenshot

Phase 185's picker behavior passed UI assertions, but its saved screenshot was covered by an Android System UI ANR. This phase made the test screenshot helper require Mama GCS to own the focused window immediately before and after capture. It saves the image first, so a failed guard retains evidence. A focused test checks that the guard accepts an app window and rejects a missing focus, the Android immersive-mode tip, an ANR and an application-error dialog. Production app behavior did not change.

The test path is Android window dump → focused-window line → app-package and error-dialog checks → screenshot assertion. The dump is read in the disposable emulator through test `UiAutomation` and is not sent, persisted or used by the app. An Android format change can make the test fail closed; the existing preflight and post-run health checks still independently inspect system errors. No permission, dependency, schema, external destination, telemetry, upload or vehicle-command path changed. Baseline `6b006cc`, clean worktree; see D-186-01.
