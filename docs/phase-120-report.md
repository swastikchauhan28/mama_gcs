## Proposed fix and verification

`VehicleMap.fitDraft` now requests an asymmetric camera fit using measured control-overlay width and a capped right inset, keeping base padding on other sides. A one-point draft retains its existing centered fit; the camera API fallback retains the existing symmetric fit. This affects presentation framing only, not draft data or command paths. The test `MissionMapDialogTest` calculates the expected asymmetric camera, and the new real-editor test requires coordinates, label layer and pixels. Wider padding can reduce zoom and may not guarantee visibility in extremely narrow maps; visual validation remains essential.
