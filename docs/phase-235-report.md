# Phase 235 — visible saved-map pack boundaries

## Goal and implementation

The owner approved a Field-map-only display of completed offline-pack boundaries, distinct from the local planning outline. Baseline `c9328fd13443966f9949661a0f5f8bfbabb8e4e9`; older untracked `output/` demo deliverables were preserved. No operator phone, Cube or rover data is needed. See D-235-01.

`OfflineFieldMaps.state` reads native MapLibre region completeness and geographic bounds. The new `completePackBoundaryRects` projection filters incomplete or invalid rectangles. `VehicleMap` turns each surviving rectangle into a closed blue line on a Field-map-only GeoJSON source, below the orange planning-outline layer. A bottom-left legend states the blue line's meaning and the number of ready packs. Source features are replaced when the pack list changes, including removal; neither source nor legend changes the persisted pack database. No additional external input, network endpoint, dependency, permission, credential or command path was added.

The list of pack rectangles is transient UI data: one rectangle per complete valid saved region, read on state changes and discarded with the map view. It contains geographic bounds already stored by MapLibre; it is not exported. Render cost rises with pack count, and overlapping or many packs can clutter the map. The blue border is a download-region hint, not a surveyed field boundary or tile-by-tile audit. The orange planning outline remains a separate local shape.
