# Phase 245: Working plan on a selected saved field map

## Scope and decision

The owner approved a software-only, default-hidden working-plan comparison on a selected saved offline map. D-245-01 records the alternatives and dated layout corrections. Baseline HEAD was `33d1e797b4890e65e99fecf3491c165029f68edd`. Earlier uncommitted Phase 243/244 tests and documents and old `output/` artifacts were preserved. No dependency, permission, schema, map provider, credential, transport or vehicle command path changed.

## Execution path and data

`MamaGcsApp` passes its in-memory `MissionPlanUiState.draft` into `SavedPackMapScreen` after Operate → Browse areas → a complete saved pack. The screen reads the selected pack's complete native bounds from `OfflineFieldMaps`, keeps the overlay hidden by default, and shows orange waypoints/route/valid outline only while the local toggle is on. `VehicleMap` reuses existing draft sources in the selected saved-pack view without entering planning mode or supplying an edit callback; the camera continues to fit the selected blue saved-area boundary. The offline warning is placed away from the fitted route on this selected-pack screen, and map controls remain compact in both toggle states so the viewport does not change.

`SavedPlanOutsidePoints` contains one-based route-point and valid-outline-vertex index lists outside the selected pack rectangle. `findPlanOutsideSavedArea` reads the immutable working draft and inclusive rectangle bounds. The result is computed for display only, is never stored or sent, and follows the existing draft limits (250 route points and 64 outline vertices). The selected map rectangle indicates cached map coverage, not surveyed field containment or route safety. Only complete packs are offered, and an incomplete outline is neither drawn nor counted. The summary truncates long index lists in the UI; the underlying comparison remains complete.

## Verification and retained failures

Two JVM comparison tests cover inclusive edges, exact one-based outside indices and incomplete outlines. A focused Android test creates only its uniquely named synthetic OpenFreeMap pack online, then a separate test process opens Operate → Browse areas → the selected pack with Android networking off. It checks default-hidden and toggled native sources, outside point labels, stable saved-pack camera target/zoom, unchanged working draft and no mission callback. It captures the Android screen for visual review and deletes only its synthetic pack in `finally`. Emulator networking is restored after each offline run.

Early test/code attempts were retained as failures, not counted as acceptance. The first compile used an unsupported Compose assertion import. The first offline run showed that a conditional text block resized the map and changed the fit; a fixed-height toggle row corrected that. A later screenshot showed the floating summary obscuring the offline warning and blue legend; the summary moved into the reserved row. Conditional compact controls then changed the map height and failed the retained zoom assertion; controls are now compact in both states. A subsequent passing source-count test screenshot still showed the top-right offline warning covering the orange route at 2× text. The warning moved to the bottom-right for the selected-pack view, and the visual test now requires actual orange pixels. The next screenshot exposed a clipped blue legend, followed by attribution overlap; the final selected-pack layout puts the blue legend upper-left and attribution lower-left. Each correction was followed by a new offline UI run.

## Limits and review

The test uses a synthetic field on a disposable emulator; no phone, Cube, GPS fix, physical rover position, actual field or mission upload was used. Seeing an orange route inside a blue cached-map rectangle does not establish tool coverage, path feasibility, offline completeness, RTK precision or safety. Review the small production diff, the new pure comparison helper, the synthetic Android test and screenshot before accepting the change. Rollback is to remove the local toggle/draft argument and selected-pack draft source allowance, returning to the previous saved-area screen; saved packs and mission data require no migration. The phase was uncommitted and unpushed at verification; the owner requested commit and push afterward, so Git history is authoritative for its current status.
