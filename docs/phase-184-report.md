# Phase 184 — Separate actions for local route warnings

The Review card now gives each existing readiness warning row its own numbered navigation action. An outside waypoint opens that waypoint in Route; a straight leg leaving the outline opens its starting waypoint; an invalid outline opens Field outline. Warning messages and their aggregation remain unchanged, so the card has at most five actions even for a 250-waypoint draft. Actions only navigate and highlight; they do not edit a draft, upload a mission, or command a vehicle.

The path is current draft → `MissionDraftReview.inspect` → bounded `MissionReviewIssue` entries (message, destination, optional one-based waypoint number) → Review action → existing editor tab and focus/scroll path. The issue list is computed in memory from the draft; it is neither persisted nor retained. Domain tests verify the mapping. Three focused real-app flows on a disposable emulator passed in 157.894 s, including simultaneous outside-point and crossing-leg warnings with separate targets. The screenshot at `app/build/reports/phase-184-readiness-actions.png` was visually inspected and shows both numbered warning actions. The focused JVM task, debug app/test APK builds and `:app:lintDebug` passed in one Gradle run (13m 20s; 97 tasks, 28 executed, 69 up-to-date).

Baseline `39360dd`, clean worktree. No new dependency, permission, schema, external destination, transport, vehicle command or safety threshold. The main limitation is that an aggregated row lists all affected indices but navigates to its first one. This remains a local drafting aid, not Cube acceptance or route safety evidence. Rollback is a reviewed revert of this scoped source/test/record diff; no data migration is needed. See D-184-01.
