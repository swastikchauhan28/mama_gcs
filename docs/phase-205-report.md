# Phase 205 — Parser context in explicit telemetry report

## Goal and scope

On 2026-11-19 the user approved adding the Phase 204 parser counts to the existing frozen telemetry report. Baseline `bb05582`, clean `main`; model/version unavailable. The report previously included total checksum failures but omitted the inside/outside rescan distinction and pending incomplete bytes. This phase changes the explicit preview and user-chosen text export only. It does not change MAVLink parsing, source selection, connection handling, storage policy or vehicle commands.

## Decision and data path

`TelemetryReportControls` passes a `VehicleState` snapshot and capture time to `TelemetryReportViewModel.prepare`. `TelemetryEvidenceReport.capture` formats an allowlisted string, which the view model holds unchanged while the operator reviews it and optionally chooses a document. The writer enforces the existing 16 KiB UTF-8 limit and closes the output stream. Three existing scalar diagnostic values now appear beside total checksum failures. Pending bytes are labeled at capture for active sessions and before close for historical sessions; the text says rescan overlap does not prove corruption. The header still records capture time and active/closed/no-session state. See D-205-01.

The counts originate from untrusted incoming bytes; they are `Long` session counters and an `Int` pending-byte count (0–280 in the parser), with no raw frame retention. The new output uses only fixed labels and numbers. A report saved to a user-chosen destination can outlive its session and be shared manually, so it must be interpreted as historical. No automatic upload or new external destination was added.

## Limits and next check

Neither count establishes packet loss, source authenticity, physical link quality or rover safety. Hardware acceptance and root-cause diagnosis remain separate. The user's explicit preview/save flow remains the only export route. Review the diff, tests and visual evidence before release; commit and push only if requested. Source-only rollback would review and reverse this cohesive diff from `bb05582`, rebuild and recheck the report; no rollback has been executed or verified as a release artifact.
