# Phase 238 — saved-area zoom and warning consistency

## Approved scope and baseline

The owner approved a bounded follow-up on 2026-11-26: open the selected saved area at a supported zoom (12–18) when it fits, preserve an accurate warning when the view extends beyond downloaded coverage, and test fitting and non-fitting synthetic areas online/offline on a disposable emulator. Baseline `0d6cafbeb971de894e5bec44d9abb10b4e39e790`; Phase 237's Android test and documentation are already dirty and must be preserved. Older untracked `output/` demo files are unrelated. No operator phone, real field, telemetry, mission upload or rover command is in scope.

The affected path is Maps settings → `View saved area` pack ID → `SavedPackMapScreen` native-complete pack lookup → `VehicleMap` MapLibre camera fit → offline zoom/viewport notice. MapLibre owns persistent tiles; the selected ID and camera state are transient. The current fit caps zoom at 18 but has no lower clamp, while the warning checks camera zoom 12–18 and the union of complete region rectangles. Complete region state and visible pixels remain availability hints, not tile auditing or field surveying.

Decision D-238-01, drafted before implementation: diagnose camera zoom and rendered notice together before changing either. Alternatives are (a) clamp every fit to zoom 12, which could clip a large pack, (b) keep the fit and warning unchanged, or (c) choose a supported zoom only when the selected bounds fit and refresh the notice from camera movement when needed. The existing fit already caps at 18 and preserves a whole pack when its fit falls below 12; Phase 236 tested a small selected pack fitting within 12–18. Phase 237's actual screen showed a zoom-range warning despite a visibly framed small pack, so this phase chose the camera-notice refresh part of (c), not a forced lower clamp. No new dependency, permission, network destination, credential, storage format or command path was added. AI model/version: unavailable. Revisit if a healthy emulator measures an actual below-12 fit for a small pack or if a real field produces contrary evidence.

## Implementation and verification

`VehicleMap` now registers a MapLibre camera-idle listener while its map is attached, removes it on disposal, and increments Compose camera revision state after a direct selected-pack fit. The offline warning reads the camera position keyed by that revision. This path keeps the existing fit and zoom/viewport warnings; it only refreshes their displayed state after camera movement. The selected ID, pack state and tile persistence are unchanged. An Android regression test opens the selected synthetic pack through Maps settings, checks its camera zoom is 12–18 and that no zoom-range warning remains, then moves to zoom 11 and expects the warning. It saves a visible Android screen capture after settling, rather than relying on MapLibre's black native snapshot. The test removes synthetic packs in `finally`.

The fresh full software gate `./gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug --no-daemon --max-workers=1 --console=plain` passed (`app/build/phase238-full-gate.txt`): 97 tasks, 28 executed/69 up-to-date. Fresh JVM XML reported 539 tests, zero failures/errors/skips; lint reported zero errors and 27 warnings. The final Android-test APK rebuilt successfully after the test-capture change (`app/build/phase238-regression-capture-build.txt`).
